# 同一布局，两套美术外观

手绘纸本现为默认。没有主题偏好、偏好无效或存储不可用时，首屏脚本与 React
均选择手绘；此前主动选择原版纸本的用户继续使用其选择。

## 布局约束

- `styles/layout.css` 集中两套外观的组件几何、字体度量和响应式规则。
- 主题样式只负责颜色、纸纹、铅笔边框、圆角、阴影和插画画面，不再调整宽高、
  间距、排版或组件位置。`theme-layout.test.ts` 防止几何规则重新进入皮肤。
- 标题笔记本、首页插画、登录介绍栏、品牌副标题等共 11 处原本只在手绘出现
  的结构现在两套共用。图标只在固定槽内切换独立图片和矢量画面。
- 统计卡改用 `stat-*` 专属类，避免评论统计卡的裸 `.comment` 类误继承真实
  评论卡样式。五卡同一行等高，图标槽统一 40 × 40 px，文本起点一致。

## 验证

- Web 测试 130 项与生产构建通过；ESLint 0 错误，保留 8 条已有警告。
- 原有浏览器回归通过：PDF、块操作、回收站、文本选择、评论锚点和主题。
- 18 个页面或状态对比，累计 4,386 个可见 DOM 组件的坐标、宽高，差异为 0
  （0.1 CSS px 容差；图标内部的图像画面不参与几何比较，外框参与）。
- 覆盖 1600 px 桌面、390 px 手机和 375 × 667 短屏；包含首页、编辑器、菜单、
  多选、搜索、管理、共享、登录和侧栏。
- 首页五卡同高 72 px；独立统计组件验证中两套桌面为 272 × 72 px、手机为
  174 × 72 px，按行一致。宽度分配的亚像素舍入不超过 0.1 px。
- 新默认、首屏回退、手动纸本偏好保留、切换后的正文/撤销/评论草稿保留均通过。

`verification.json` 记录实际 AppRoot/Tiptap 检查。截图使用独立内存 REST 数据，
仅验证环境关闭 Yjs 传输；未修改用户数据库或生产协作配置。
