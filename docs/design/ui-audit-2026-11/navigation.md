# 导航与页面上下文

审计 §2、§3 里"入口归属"和"页面上下文"两组的落地记录。契约见 `CONTRACTS.md` §6。

## 1. 一个打开规则

`apps/web/src/lib/open-target.ts` 是唯一答案，纯函数：

- `openTarget(doc)` → 文件夹给 `{ kind: 'folder', folderId: doc.id }`，文档给
  `{ kind: 'document', doc, parentFolderId, trashed }`。
- `viewForTarget(target)` → 对应的 shell 状态（`active` / `selectedFolderId` /
  `homeView`）。

修掉的三个具体错误：

| 位置 | 旧行为 | 现在 |
| --- | --- | --- |
| 搜索结果、首页卡片 | 对文件夹执行 `setActive(folder)` 再 `setSelectedFolderId(folder.parentId)`，把上级目录当作选中项，根部则清空选择落回首页；某些情况下还会把文件夹挂进编辑器 | 文件夹进文件夹页 |
| 文件夹页 | 文件夹正确，但打开文档时忘记设 `homeView`，文件夹页留在下面 | 文档进编辑器 |
| 侧栏树 | 各自复制了一份两半逻辑 | 同一个解析器 |

所有入口（侧栏树、面包屑、首页、收藏、最近、搜索结果、命令面板、文件夹页）都走
`openDocTarget`，`test/open-target.test.ts` 覆盖嵌套文件夹、根级文档、回收站行。

## 2. 搜索不再打断写作

旧行为：侧栏搜索每输入一个字符就 `setHomeView('search')` + `setActive(null)`，
编辑器被卸载，光标和滚动位置一起丢失。

现在：

- 输入只改 `query`。文档树用它过滤（`treeQuery`），编辑器不卸载，`.editor-column` 的
  `key` 不含 query，所以光标与滚动天然保留。
- **进入结果页是显式第二步**：回车，或侧栏里出现的"查看全部结果"行（该行只在有查询时
  存在）。结果页有自己的标题、返回动作。
- Escape 清空查询并把焦点还给输入框，文档仍是原来那篇。
- Ctrl+K 的命令面板维持原样：它是键盘优先的浮层，本来就不离开文档。

`test/search-continuity.test.ts` 断言搜索处理函数里不再有 `setActive(null)`，并说明这只
是"没有卸载"的代理指标——真正的证据是浏览器里打字后光标仍在原位，本轮没有做该实测。

## 3. 页面只显示能生效的控件

`TopBar` 现在以 `hasDocument` 为分界：

- **有文档**：侧栏开关、路径与标题、保存状态、在线成员、评论、共享、更多。
- **无文档**（首页、文件夹页、搜索结果、回收站、所有文档、管理页）：侧栏开关、路径与
  标题。保存状态、在线成员、收藏、导出、历史、评论、共享一律不渲染，而不是渲染成一排
  灰色图标——灰按钮在说"这个功能存在但暂时不可用"，而这些页面上它根本不存在。

文档动作收敛到 文档"更多"（`components/layout/DocumentMenu.tsx`）：导出（PDF/Markdown/
HTML/JSON）、打印、版本历史、收藏、移动到、文档信息。评论与共享留在顶栏，因为它们是
写作中途会伸手去点的两个动作。

外观（`ThemeMenu`）从文档顶栏移到侧栏账户行：它是浏览器级偏好，放在文档顶栏暗示它是
文档设置。

## 4. 诚实命名

审计指出两处标签与口径不符，两者情况不同：

- **首页的"最近访问"卡片**：确实只是按 `updatedAt` 取前 6 篇，不是访问记录。已改名
  "最近更新"。而侧栏的**"最近"页面**是另一回事——它读服务端
  `GET /api/v1/documents/recent`，是这个账号真正的打开记录，标签是准确的，保持不变。
- **"我创建的"**：`Doc` 类型没有创建人字段，服务端也没有按创建人筛选的接口，所以那一段
  实际上是"全部文档"。已改名"全部文档"。真正的个人视图需要服务端字段。

改名而不是补数据，是因为在没有数据的情况下补一个看起来个性化的列表只是把错误藏起来。
