# 审计落地：批次 A 记录

对应 `marvelous-docs-ui-audit.md`（2026-11-16，版本 0.1.75）。本文件记录**已实现**与**已测量**的部分，
以及仍然只是规划的条目。不要把本文件当成"全部完成"的证明：每一行都标了证据等级。

证据等级：

- **测试** — `apps/web/test/*.test.ts` 里有断言，`pnpm --filter @marvelous-docs/web test` 通过。
- **源码** — 只核对了代码路径，没有运行行为验证。
- **未验证** — 需要真机输入法、真实浏览器布局或真实延迟测量，本轮没有条件执行。

## 1. 操作准确性（审计 §3 P1）

| 发现 | 处理 | 证据 |
| --- | --- | --- |
| 图片工具取第一张可见图片 | 工具目标改由选区解析：只有 `NodeSelection` 落在图片上才出现。 | 测试 `selection-target.test.ts`：同屏两图，选中第二张时返回第二张；光标落在图片后的段落时返回 `null`。 |
| 表格工具贴第一张可见表 | 从 `$from` 向上找 `table` 祖先（也接受整表 NodeSelection），工具只锚定该位置；该位置节点已不是表格时整条工具消失。 | 测试：光标在第二张表内 → 解析出第二张表的位置，且不等于第一张；表外光标 → `null`。 |
| 协作删除对象后旧工具仍存活 | 表格/图片工具在每次 `transaction` 重新解析，节点不存在即卸载。 | 源码 `DocumentEditor` 的对象目标 effect + `TableMenu` 的 `nodeAt` 校验。浏览器协作删除未实测。 |
| 浮层在软键盘下不可用 | 两条块工具的定位从 `innerWidth/innerHeight` 改为 `visualViewportRect()`。 | 源码。软键盘实测未做。 |

## 2. 中文输入保护（审计 §3 P1）

- 新增 `lib/editor/ime.ts`：`isComposing` + 旧 WebKit 的 `keyCode 229` + `compositionend` 之后 60ms 宽限，
  只拦命令键（Enter/Escape/方向键/Tab），不拦普通字符。
- 斜杠菜单的 document 捕获阶段监听套用该守卫；标题输入框的 Enter/Escape 同样套用。
- 证据：测试 `selection-target.test.ts` 覆盖"候选确认的 Enter 不执行命令""组合结束后立刻输入不被拦"
  "宽限期过后故意按的 Enter 不被吞掉"。
- **未验证**：真实 Windows 微软拼音 / 搜狗 / macOS 拼音的实际事件顺序与 60ms 是否足够。这需要真机会话，
  本轮没有做，也不能用单元测试代替。

## 4. 计数口径（审计 §3 P1）

`CharacterCount` 的默认 `wordCounter` 按空格分词，中文段落算 1 个字。现在给它传入 `lib/format.wordCount`
（CJK 按字、拉丁按词），沿用扩展的增量存储，所以页脚既是准的也不是每键 O(n)。
证据：测试 `word-count.test.ts` 断言传入的就是同一个函数引用，而不只是"行为一致"。
