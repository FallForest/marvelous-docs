# 手机能力矩阵（max-width: 560px）

审计 §5 的结论是"问题的根源是功能收起后没有承接完整，并非按钮太小"。本文件是承接表，
也是 `apps/web/test/phone-capability.test.ts` 所断言的内容。

规则：**手机上命令可以换位置，不可以消失。** 一个命令要么在格式条上，要么在"更多"里。
CSS 隐藏某个分组，同一个改动必须让"更多"里出现对应行；测试会在缺失时报错。

## 格式条（按 360px 一行可容纳）

| 位置 | 命令 |
| --- | --- |
| 历史 | 撤销 |
| 段落 | 段落样式选择（正文/标题 1/2/3） |
| 文字 | 加粗 |
| 插入 | 图片 |
| 溢出 | 更多格式 |

重做不在行上：从 760px 起就被 CSS 隐藏，"更多 → 历史"是它唯一的入口。

## "更多格式"面板（自上而下，扁平，无二级菜单）

| 分区 | 内容 |
| --- | --- |
| 段落 | 正文、标题 1、标题 2、标题 3 |
| 文字 | 加粗、斜体、下划线、删除线、行内代码、字号 |
| 颜色 | 文字颜色色板 + 默认颜色；高亮色板 + 清除高亮 |
| 对齐 | 左、居中、右、两端 |
| 列表与块 | 项目符号、编号、任务、引用、代码块 |
| 缩进 | 减少、增加 |
| 插入 | 图片、链接、表格、分割线、换行符 |
| 导航 | 查找替换、文档大纲 |
| 历史 | 重做 |

"扁平"是刻意的：一行再开一个弹出层，手机上就是两次展开，且第二次的位置取决于第一次，
容易点错。"查找替换"和"文档大纲"会关掉菜单打开自己的面板，这是仅有的两个会跳转的行。

## 可用性

- 每一行 44px 高（`.tb-more-menu .tb-menu-item{min-height:44px}`），色板也同样放
  大到可点。
- 面板在自身内部滚动，`overscroll-behavior:contain`，高度受 `Popover` 按
  `visualViewport` 算出的上限约束——软键盘弹出时上限变小，面板跟着变矮，不会伸到键盘
  下面。
- 色板是 `role="menuitem"` + `aria-pressed`，`aria-label` 带颜色中文名，不是只有背景
  色的裸按钮。
- 只读文档下所有行与色板都 `disabled`，与桌面一致。

## 未验证

- 360 / 390 真机上的实际命中率与拇指可达性；只有 44px 这个下限被样式保证。
- 软键盘弹出时"更多"面板的实际位置：上限用的是 `Popover` 已有的 `visualViewport`
  逻辑，但本次没有在真机键盘下实测。
- 中文输入法在手机上的候选窗与面板是否互相遮挡。
